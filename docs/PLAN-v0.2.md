# 薪时 v0.2 · 记工更省事

> 版本：0.2.0 ｜ 日期：2026-11-04 ｜ 状态：已实现并通过验收
>
> 后续版本：[v0.3 计件 / PDF / 加密备份](PLAN-v0.3.md)。
>
> 主题：**少填一点，记快一点。** 在不改动 v0.1 账务模型的前提下，把「记工」这件事做得更顺手。

---

## 1. 版本目标

v0.1 解决了「算得清、结得明」。v0.2 解决「记起来麻烦」：

1. 下班时不用回想几点上班 —— **打卡计时**。
2. 想按日期看哪天有活 —— **日历视图**。
3. 忙起来忘了记 —— **每日提醒 + 系统日历**。
4. 和老板对账需要一张图 —— **工资条图片**。
5. 晚上看账不刺眼 —— **深色模式**。

范围仍坚持个人侧、本地优先、无后端；不引入账号、云同步或支付。

## 2. 功能设计

### 2.1 打卡计时

- 入口：首页「今天」卡片的「计时」按钮；多份工作时先选工作，只有一份工作时直接开始。
- 运行卡：工作、实时时分秒、开始时间、结束按钮、放弃按钮；底部导航首页出现琥珀小圆点。
- **持久化**：计时开始时间写入 `activeTimer`，刷新、关页面、重新打开都会继续计时。
- 结束：把开始时间、当前时间、开始日期带入「记一笔」，用户确认休息 / 加班 / 奖扣后再保存。
- 不足 1 分钟：按 1 分钟带出，避免 0 工时无法保存。
- 超过 24 小时：卡片提示，结束仍可打开工记，但会提醒核对，防止忘记结束。
- 约束：
  - 同一时间只允许一个计时；
  - 正在计时的岗位不能归档 / 删除；
  - 取消计时需二次确认，取消后不生成工记。
- 取舍：v0.2 不做暂停、多计时器、后台常驻秒表；这些留到后续。

### 2.2 日历视图

- 记录页增加「列表 / 日历」切换，月份切换、工作筛选与列表共享。
- 月历以周一 / 周日为起始（跟随「一周从哪天开始」设置）。
- 有工记的日期显示最多 3 个岗位色点；今天琥珀描边，选中日深绿底。
- 点选日期后，下方显示该日总工时、总收入和工记列表，可直接打开详情。
- 不在格子里塞金额，避免小屏拥挤；金额在选中日摘要中显示。
- 空日期仍可点选，显示「这天没有工记」和补记入口。

### 2.3 记工提醒

- 「我的 → 提醒」：开关、提醒时间（默认 21:00）、浏览器通知权限、测试通知。
- 浏览器通知：
  - 到点且今天没有工记时提醒，每天最多一次；
  - 只在页面处于前台时检查（每 30 秒 + 回到前台时）；
  - 权限被拒绝时不影响其他功能。
- **系统日历**：生成每日重复 365 天的 `.ics` 文件，导入手机日历后即使 App 关闭也能提醒。
  - 这是对 PWA 无法可靠后台定时通知的诚实补足，而不是假装能后台推送。
- 限制会直接写在界面上，不承诺做不到的事。

### 2.4 工资条图片

- 入口：已结算单底部「工资条」。
- Canvas 现场绘制 1080×1440 PNG，不经过服务器：
  - 品牌头、工作、周期、应发净额；
  - 基础 / 加班 / 奖金 / 扣款 / 借支抵扣明细；
  - 出勤、工时、加班统计；
  - 备注、结算时间、防伪「已结算」章。
- 支持下载；浏览器支持 `navigator.share({ files })` 时支持系统分享。
- 图片使用结算快照，后续数据变化不影响已生成内容。
- 图片固定为浅色暖纸风格，方便打印 / 转发；深色模式只影响 App 界面。

### 2.5 深色模式

- 三档：跟随系统 / 浅色 / 深色，保存在本机并随备份导出。
- `data-theme` 在页面脚本中预置，避免刷新时白闪；系统主题变化实时跟随。
- 深绿黑背景 + 暖白文字 + 琥珀强调，保持「暖纸账本」而不是纯黑后台。
- 全部页面、抽屉、对话框、工资条弹层、Toast 均适配；岗位颜色在深色下用低饱和混色。
- 同步更新 `theme-color`，让浏览器 / PWA 状态栏跟随。

## 3. 数据与迁移

### 3.1 schema v2

```ts
interface Settings {
  weekStartsOn: 0 | 1;
  theme: 'system' | 'light' | 'dark';
  reminder: { enabled: boolean; time: string };
}

interface WorkTimer {
  jobId: string;
  startedAt: string; // ISO 时间戳
}

interface AppState {
  version: 2;
  // ... v0.1 字段
  settings: Settings;
  activeTimer: WorkTimer | null;
}
```

- 存储键升级为 `xinshi.state.v2`；启动时优先读 v2，失败则读 `xinshi.state.v1` 并迁移。
- 旧数据缺失的字段补默认值：`theme=system`、`reminder={enabled:false,time:'21:00'}`、`activeTimer=null`。
- 导出包版本升为 2；**仍接受 v1 备份**导入，导入后统一升级到 v2。
- 计时器引用不存在 / 已归档工作时自动丢弃，避免坏状态。
- 已用真实 v0.1 localStorage 数据验证迁移：旧账本、工作、工记、结算可正常打开。

### 3.2 兼容性

- 旧用户无需操作，首次打开 v0.1 数据会自动迁移。
- 旧版导出的 JSON 可直接导入。
- 新版导出的 JSON 在 v0.1 中无法读取（version 2），这是预期行为，建议同步升级。

## 4. 视觉与交互补充

- 计时卡：琥珀图标 + 大号等宽秒表 + 结束 / 放弃；不用红色制造焦虑。
- 日历：圆点表示「哪几天有活」，选中日展开明细；避免在 44px 格子里塞金额。
- 提醒：明确写「网页通知只在 App 打开时生效」「加到系统日历，关掉 App 也能提醒」。
- 工资条：沿用暖纸 + 深绿 + 琥珀，让图片即使离开 App 也有品牌辨识度。
- 深色：使用 `color-mix` 给岗位色做低饱和背景；选中态、主按钮、图表单独调深绿色，避免亮绿配白字对比不足。

## 5. 验收

### 5.1 单元测试（33 / 33）

- v0.1 计薪 / 结算 / 周期：22 个，全部保持通过。
- 存储迁移：5 个（v1 → v2、v2 字段、非法计时器、导出、未来版本）。
- 计时：4 个（格式化、秒数、带出时间、超 24h）。
- 提醒：2 个（到点判断、ICS 规则）。

### 5.2 浏览器验收

- 计时：开始 → 刷新继续计时 → 结束带出 → 保存为工记；底部导航圆点。
- 日历：切换、月历格、选中日明细、工作筛选。
- 提醒：开关、时间、系统日历 .ics 下载；权限状态展示。
- 工资条：生成图片（blob 加载成功）、下载 PNG（>30KB）。
- 深色：切换、刷新保持、全页面无白块。
- v0.1 回归：22 个计薪测试 + 原有浏览器流程 + 离线刷新。
- 响应式：320 / 360 / 390 / 430 / 768 / 1280px 无横向溢出。
- 控制台错误：0。

### 5.3 已知限制

- **提醒**：纯前端 PWA 无法可靠后台定时；浏览器通知需要 App 打开。系统日历文件是可靠替代，但需要用户导入一次。
- **计时**：同时只能一个；不支持暂停；跨 24 小时需人工核对；结束计时后关闭工记不会自动保存。
- **工资条**：固定 PNG、浅色版式、最多展示主要金额项；不支持自定义模板 / 公司抬头。
- **深色**：工资条图片保持浅色；系统级状态栏颜色取决于浏览器。
- **同步**：仍然没有云同步，换设备请导出 / 导入。
