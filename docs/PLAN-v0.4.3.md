## 1. 删除后可撤销

### 1.1 Toast 支持一个动作

- Toast 增加可选的 `action: { label, onClick }`；
- 带动作的提示停留 **5.2 秒**，普通提示仍是 2.8 秒；
- 点动作会先关闭当前提示，再执行恢复，恢复成功会再给一条「已恢复」提示；
- 不改变原有 `toast(message, tone)` 调用。

### 1.2 删除工记

删除确认后：

- 工记立即从列表移除，详情关闭；
- 底部 Toast：「工记已删除 · 撤销」；
- 点「撤销」把原工记（含原 id / createdAt / 当时规则）放回；
- 恢复前会检查：
  - 原工作是否还存在；
  - 周期是否已经被结算；
  - 当天其他工记 + 这笔是否超过 24 小时；
- 任一条件不满足，恢复失败并提示，不会写入半条脏数据。

### 1.3 取消休息

点「取消休息」后：

- 休息标记移除，弹层关闭；
- 底部 Toast：「已取消休息 · 撤销」；
- 点「撤销」恢复原休息记录；
- 如果这期间同一天已经补了工记、重新标了休息或周期已结算，恢复会失败并提示。

### 1.4 边界

- 撤销只保留约 5 秒；关闭 Toast 或出现下一条提示后不可撤销。
- 撤销恢复的是删除瞬间的快照，不会恢复删除后新改的关联数据。
- 已结算工记仍然不能删除；已结算休息仍然不能取消。
- 工作删除、借支删除暂未接入撤销。

## 2. 工作设置返回提醒

### 2.1 触发

编辑 / 新建工作时，只要任意设置发生净变化：

- 工作名称、雇主、颜色；
- 计薪方式、单价、计件单位、结算周期；
- 月薪模式、月休额度、标准工时、计薪天数；
- 班次、午休；
- 加班开关和倍率。

点左上角返回、或按 Android 返回键，会先问：

> 放弃这次修改？  
> 工作设置还没有保存，返回后这些修改会丢失。

- 「取消」留在当前页；
- 「放弃」才返回；
- 改完又改回原值，视为未修改，不打扰；
- 保存成功、归档、删除会直接离开，不弹提醒。

### 2.2 Android 返回键

- 工作设置页自己接管返回键，不再由 App 最外层直接关页面；
- 有未保存修改时，返回键先弹确认；
- 确认弹层打开时，返回键优先关闭弹层；
- 保存后返回、归档、删除仍走正常返回。

## 3. 不改什么

- 不改变 PayRule / Entry / RestDay / Settlement 数据模型；
- 不改变存储 schema（仍是 v4），旧数据不需要迁移；
- 不改变计薪、结算、固定月薪、休息额度规则；
- 撤销只恢复被删对象，不改变其他工记或结算。

## 5. 已知限制

- 撤销窗口约 5 秒；超时后无法恢复。
- 撤销不覆盖删除工作、删除借支。
- Toast 只支持一个动作，不做多条操作队列。
- 工作设置页返回提醒不覆盖应用内其他子页面（结算页等）。
- 云同步仍未实现，见 [CLOUD-SYNC](CLOUD-SYNC.md)。
