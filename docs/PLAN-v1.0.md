# 薪时 v1.0.0 · 「留得住 · 看得见」离线考勤照片与数据边界收口

> 版本：1.0.0 ｜ 日期：2026-11-06 ｜ 状态：**已实现**
>
> 一句话：**给工记留一张带水印的现场照片，同时把 0.9 遗留的数据边界、导入与恢复规则一次收口。**
>
> 基线：v0.9.0（169 单测 / 110 浏览器场景 / APK 3.3MB / schema v7）。

---

## 1. 为什么是 1.0.0

v0.9.0 把「删了能找回」补齐后，账本已经能长期使用。1.0 不再继续堆功能数量，而是解决两件更基本的事：

1. **留痕**：工记只有时间和金额，遇到争议时缺少现场证据。本版允许在记一笔时拍照 / 选图，压成带岗位、日期、工时水印的照片，只存本机。
2. **稳定**：把「同日 24 小时」「休息与工记互斥」「结算周期重叠」「导入坏数据」这些规则从界面提示下沉到数据层，避免绕过界面写入坏账本。

数据格式**冻结在 schema v7**：只新增可选 `Entry.photoId`，不升级存储键，旧备份 / 搬家包 / 本机快照继续兼容。

### P0（已修）

| 编号 | 发现 | 处理 |

| A1 | 同日 24 小时上限只写在 EntryEditor，`addEntry` / `updateEntry` 本身不校验 | 新增 `src/lib/guards.ts`，Store 写入前统一校验；超限返回失败 |

| A5 | 工记删除确认仍写「5 秒内可撤销」 | 改为「进入回收站，30 天内可恢复」 |

## 3. 交付内容

### 3.1 考勤照片（离线水印）

- **入口**：记一笔 → 考勤照片（选填）→ 拍照或从相册选择。
- **压缩与水印**：
  - 长边 ≤ 1280，JPEG quality 0.72；超过 600KB 自动降到 1024 / 0.62。
  - 水印包含「薪时 · 考勤留痕」、岗位名、`YYYY.MM.DD 周X · 在岗 X 小时`、`拍摄 HH:mm · 仅存本机`。
  - EXIF 方向优先用 `createImageBitmap` 处理，失败回退 `Image`。
- **存储**：
  - `src/lib/photos.ts`，IndexedDB `xinshi.photos`，store `photos`，keyPath `id`。
  - 账本只存 `Entry.photoId`，照片本体不进 `localStorage` / 备份 / 搬家包 / 本机快照。
- **查看与保存**：工记详情显示缩略图，点击打开大图，可保存到 `Download/Xinshi/`。
- **清理**：彻底删除工记 / 工作、清空回收站、清空所有数据都会删除照片；启动时清理无引用照片。
- **权限**：不申请 CAMERA；通过系统文件选择器调用相机 / 相册，不读取相册其他内容。

### 3.2 文字版 PDF 多页

- 新增 `src/lib/payslipDetail.ts`：按 `settlement.entryIds` 取锁定工记，按日期升序生成明细。
- 文字版 PDF 在结算摘要后附「工记明细」页，每页 36 行，续页带表头与页码。
- 休息日期 / 备注过长时自动换页，不再越过 A4 底边；二维码与校验码固定在摘要第一页。
- 工资条设置新增「工记明细」开关；完整版 / 简洁版默认开启，只发金额默认关闭。
- 图片版 PDF 仍为单页 1080×1440。

### 3.3 回收站按工作筛选

- 类型筛选（全部 / 工记 / 休息 / 借支 / 工作）+ 工作筛选（全部工作 / 具体工作）同时生效。
- 汇总（待处理条数、金额、工时、休息天数）跟随筛选结果。
- 切换类型后若当前工作在新类型下没有记录，自动回到「全部工作」。
- 只有回收站涉及 2 份以上工作时才显示工作筛选，避免单工作用户多一层选择。

### 3.4 数据格式冻结

- `SCHEMA_VERSION = 7` 保持不变，存储键仍为 `xinshi.state.v7`。
- 新增字段一律可选；旧备份缺省为空。
- 后续版本只允许新增可选字段，不再升级存储键；破坏性变更需单独发布迁移工具。

## 4. 不做 / 留到后面

- **桌面小组件、轮班 / 排班表、按小时请假**：留到 v1.1。
- **工头台账 / 多人分账**：需要新数据模型与权限边界，继续评估。
- **回收站分页 / 虚拟列表**：每类 120 条上限内可不分页，v1.1 再看。
- **照片云同步 / 备份内嵌照片**：会显著放大 JSON / 加密包体积，本版坚持本机存储。
- **云同步 / 账号 / 广告 / 统计 SDK**：继续暂停，不引入网络权限。
