# 薪时 v0.9.0 · 「删了也能找回」统一回收站与全量审计

> 版本：0.9.0 ｜ 日期：2026-11-06 ｜ 状态：**已实现**
>
> 一句话：**把工记、休息、借支也纳入回收站；同时把前后端代码审计出的数据安全问题一次性收口。**
>
> 基线：v0.8.0（APK 3.3MB / 首屏 JS 130.17KB gzip / 155 单测 / 105 浏览器场景 / 分辨率矩阵 135+16 全绿）。

---

## 1. 为什么是 0.9.0

v0.8.0 把「找得到、看得远」补齐后，账本里还剩一个明显的安全缺口：

- 工记、休息、借支删除后只有 5 秒 Toast 撤销，Toast 一过就真的没了；
- 工作回收站只收空工作，删除有休息日的工作会静默连休息日一起清掉；
- 「统一条目回收站」原本就是 v0.8 明确留到下一版的事。

本版以它为主线，并对前后端（React UI + 本地数据层）做了一次系统审计，把
类型、导入、恢复校验、容量、可访问性等底层问题一起修掉。不新增计薪规则、
不引入网络 / 账号 / 新权限，数据仍是 schema v7，旧备份继续可导入。

## 2. 审计发现与处理

### P0（已修）

| 编号 | 发现 | 处理 |
| --- | --- | --- |
| A1 | 回收站功能处于半成品状态：`types.ts` 已加三类回收站字段，但 `storage.ts` / `seed.ts` / 测试夹具未同步，`pnpm typecheck` 直接失败 | 补齐默认值、导入规范化、示例数据与测试夹具；修正 `trash.ts` 可空日期未收窄 |
| A2 | `deleteJob` 会静默删除该工作下的所有休息日，且没有提示 | 改为「有工记、借支、休息或结算的工作只能归档」；Store 与 JobEditor 的 `canDelete` / 文案同步 |
| A3 | 工记 / 休息 / 借支删除只有 5 秒撤销，超时后不可恢复 | 新增四类统一回收站：删除即入站，30 天内可恢复 |

### P1（已修）

| 编号 | 发现 | 处理 |
| --- | --- | --- |
| B1 | 导入校验完全忽略新的回收站数组，导入会静默丢弃；回收站记录指向「回收站里的工作」时整份备份会被拒绝 | 新增三类规范化；活动工作 + 回收站工作合并校验；坏掉的单条回收站记录跳过而不拒绝整包 |
| B2 | 导入未校验重复 ID，重复工记会让编辑 / 删除命中多条记录 | 工记 / 借支 / 结算重复 ID 直接拒绝导入 |
| B3 | 回收站无容量上限，过期清理只覆盖工作类 | 每类最多 120 条；四类都在导入 / 启动时按 30 天清理 |
| B4 | 彻底删除工作后，指向它的回收站记录变成无法恢复的死数据 | 彻底删除工作时级联清理其工记 / 休息 / 借支副本 |
| B5 | Toast 撤销恢复成功后，回收站仍保留副本，可能重复恢复 | 所有恢复路径同时移除回收站副本 |
| B6 | 抽屉 / 确认框无焦点管理：打开不聚焦、关闭不归还、Tab 会跑到背景页；嵌套确认框按 Esc 会连抽屉一起关 | 新增 `useModalFocus`：初始焦点、Tab 循环、关闭归还；确认框 Esc 只关最上层 |
| B7 | 回收站入口只在「工作管理」里、且只有已删工作时才出现；删工记后几乎找不到 | 「我的 → 数据」新增回收站入口；工作管理入口按四类总数显示 |

### P2（已修）

| 编号 | 发现 | 处理 |
| --- | --- | --- |
| C1 | 回收站只有工作列表，无筛选、无汇总，条目多时不可读 | 全部 / 工记 / 休息 / 借支 / 工作筛选，金额 / 工时 / 休息天数汇总，单条恢复原因 |
| C2 | 版本号在浏览器 / Android 验收脚本里硬编码 0.8.0，升级即失败 | 脚本统一读 `package.json`；版本号仍只有一处来源 |
| C3 | 删除工作提示没有提到休息 / 借支 | 文案更新为「有工记、借支、休息或结算的工作只能归档」 |

### 审计确认、未改动

- 计薪（时薪 / 日薪 / 月薪 / 计件、加班倍率、月薪封顶）未发现回归；保持原算法。
- 快照 / 加密搬家包 / 自动备份 / 账本体检链路未发现新的数据破坏点；只确认它们会自动带上新字段。
- 搜索 / 年度统计口径不变。

## 3. P0 范围（已交付）

### P0-1 四类统一回收站

- 删除工记（详情页）、取消休息（记休息 / 考勤 / 月结补标）、删除借支、删除空工作，都进入回收站。
- 每类保留 30 天、最多 120 条；超期或超量自动清理。
- 回收站支持：
  - 筛选：全部 / 工记 / 休息 / 借支 / 工作；
  - 汇总：待处理条数、涉及金额、工时、休息天数；
  - 恢复：恢复到原日期 / 原工作，恢复前先校验；
  - 彻底删除：单条确认 + 清空回收站确认；
  - 恢复原因：原工作已删除 / 原工作还在回收站 / 周期已结算 / 同日超过 24 小时 / 休息与工记冲突。
- 入口：我的 → 数据 → 回收站；工作管理 → 回收站（有记录时显示总数）。

### P0-2 数据层收口

- `AppState` 新增 `trashedEntries / trashedRests / trashedAdvances`，schema 仍为 v7。
- `validateImport` 规范化三类回收站；允许引用仍在回收站的工作；跳过坏条目；拒绝重复 ID。
- `createEmptyState` / 示例数据 / 测试夹具同步。
- 工作彻底删除时级联清理其回收站副本。

### P0-3 审计修复与打磨

- 工作删除保护：有休息日也只能归档。
- 弹层焦点：打开聚焦、Tab 循环、关闭归还；嵌套确认框 Esc 只关最上层。
- 回收站 320px 无横向溢出，深色模式使用主题变量。
- 版本号 0.9.0：`package.json` / Android `900` + `0.9.0` / Service Worker 缓存 v23。

## 4. 不做 / 留到后面

- **工头台账 / 多人分账**：仍需新数据模型与权限边界，继续评估 1.0。
- **回收站分页**：受每类 120 条上限约束，最多 480 行，暂不做分页 / 虚拟列表。
- **按小时请假、PDF 多页、桌面小组件、拍照水印、轮班表**：继续排后续。
- **云同步 / 账号 / 广告 / 统计 SDK**：继续暂停，不引入网络权限。
- **数据格式**：仍是 schema v7；新增字段为可选，旧备份 / 搬家包 / 快照完全兼容。
