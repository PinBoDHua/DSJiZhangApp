# 薪时 v0.6.0 · 账本有底（无服务器版）

> 版本：0.6.0 ｜ 日期：2026-11-05 ｜ 状态：**已实现并通过验收**
>
> 一句话：**不登录、不联网、不上传**，用「本机时光机 + 加密搬家包 + 自动离机备份 + 账本体检 + Excel 对账」把「换手机不丢账、账目查得清」做实。
>
> 本计划**取代**原路线图里的「v0.6 账号 + 云同步」。没有可托管服务器，云同步不做半成品；原 [CLOUD-SYNC](CLOUD-SYNC.md) 设计保留为未来自托管参考，不进入本版。

---

## 1. 决策：砍掉云，换成什么

### 1.1 为什么不继续做云

| 原计划 | 现实 | 0.6.0 的决定 |
| --- | --- | --- |
| 账号 + 登录 + 端到端加密同步 | 需要服务器、域名、HTTPS、数据库、备份、监控 | 不做 |
| 多设备实时一致 | 需要冲突合并协议与长期运维 | 不做实时同步 |
| 托管部署模板 | 长期成本、隐私合规、客服责任都在个人开发者身上 | 不做托管 |
| 「数据在云端」的心智 | 半成品登录会让用户误以为已经备份 | 明确写「数据只在本机」 |

**判断**：0.6 的价值不是「多端实时同步」，而是**没有服务器也能换机、找回、对账**。把「云」换成「文件」，是这一版的核心取舍。

### 1.2 换来的四件事

1. **换手机**：一个加密文件，带预览、校验和回滚。
2. **误删 / 改错**：本机时光机回到任意快照，不依赖网络。
3. **数据坏了**：账本体检发现不一致，安全项可修复。
4. **对账**：Excel 四张表，给老板、银行、家人看。

### 1.3 不变的原则

- 本机 `localStorage` 仍是**唯一事实源**；所有新机制都是镜像和保险，不改变计薪与结算规则。
- 不因为备份、体检、导出而阻塞记工。
- 任何恢复、导入、清空之前，先给当前状态拍一张快照。
- 不新增网络请求、不上传任何字段；Android 不新增权限。

## 2. 现状与缺口

| 维度 | 现在（v0.5.14） | v0.6.0 之后 |
| --- | --- | --- |
| 存储 | `localStorage` 整包 JSON，schema v7 | 不变，另加 IndexedDB 快照 |
| 手动备份 | 普通 JSON / AES-GCM 加密 JSON | 保留，入口收敛到「数据与安全」 |
| 自动备份 | 无；只有「14 天没备份」提醒 | Android 每日写入下载目录，保留 14 份 |
| 导入 | 整包覆盖，只显示导入包的条数 | 识别搬家包，校验 + 与本机对比 + 先拍快照 |
| 误删 | 5 秒撤销；之后不可恢复 | 快照回滚（回收站排 0.6.1） |
| 数据检查 | 无 | 14 组体检，按严重 / 提醒 / 提示分组 |
| 导出 | CSV（月流水 / 考勤）、PDF、PNG、二维码 | 新增 Excel（工记 / 月汇总 / 结算 / 借支） |
| 多端 | 手动导出导入，无标准格式 | 标准搬家包 + 第三方文件同步指南 |
| 云 | 未实现 | 明确不排期 |

**最痛的一条**：首页在备份到期时会说「换手机或清缓存会丢账」，但用户真正能做的只有「记得导出」。0.6.0 要把这句话从提醒变成机制。

## 3. 方案总览：三层保险

```
记一笔 ──> localStorage（唯一事实源，schema v7）
              │
              ├─ 每 3 分钟空闲 / 关键操作前
              │     └─> 本机时光机（IndexedDB，gzip，最多 30 份）──> 误操作回滚
              │
              ├─ 每天首次打开 / 结算后
              │     └─> 自动离机备份（Download/Xinshi/自动备份，保留 14 份）──> 卸载、清缓存
              │
              └─ 手动 / 换手机
                    └─> 加密搬家包（文件 / 微信 / 网盘 / Syncthing）──> 另一台设备

账本体检：只读扫描，发现不一致；安全项一键处理
Excel：从同一份账本生成四张对账表
```

三条边界，写在界面上：

1. **快照不是离机备份**：清站点数据 / 卸载 App 会一起没。
2. **自动备份默认关闭**：用户主动开启后才写文件；开启后是明文，界面明确提示，要保密请用加密搬家包。
3. **搬家包不是实时同步**：没有「另一台设备改了我这边自动变」；导入是替换，先预览再确认。

## 4. P0-1 本机时光机

### 4.1 触发

| 时机 | 说明 |
| --- | --- |
| 空闲快照 | 状态变化后防抖 3 分钟；内容没变则跳过 |
| 每日首开 | 距上次快照超过 6 小时，且当天还没拍过 |
| 关键操作前 | 导入、清空、恢复快照、撤销结算前 |
| 手动 | 数据与安全页「现在拍一张」 |

### 4.2 存储

| 项 | 设计 |
| --- | --- |
| 位置 | IndexedDB `xinshi.snapshots`（v1），独立于 localStorage |
| 记录 | `{ id, at, reason, schema, hash, bytes, compressed, manifest }` |
| 内容 | `AppState` 的 JSON，优先 `CompressionStream('gzip')`，不支持则存原文 |
| 去重 | SHA-256 前 12 位相同则跳过 |
| 保留 | 最近 10 个自动 + 每日首个 7 个 + 手动 5 个（去重后约 20 份），硬上限 30 个 |
| 上限 | 总占用 30 MB；超出按「最旧自动 → 最旧每日」淘汰 |
| 失败 | 空间不足时清一批旧快照重试一次；仍失败只提示，不影响记工 |

### 4.3 恢复流程

1. 选快照 → 显示快照时间、原因、条数、累计工时、工记合计（每条记录合计相加，仅作对比，不等于结算应发）。
2. 与本机对比：工作 / 工记 / 休息 / 借支 / 结算的 **条数差**，总工时与应发 **差额**。
3. 确认文案：「用 10:32 的状态覆盖当前账本？当前状态会先存一张快照。」
4. 恢复后 Toast 提供「撤销这次恢复」（回到恢复前快照）。

### 4.4 降级与限制

- IndexedDB 不可用（隐私模式 / 存储被禁）：页面显示「本机快照不可用」，只保留文件备份。
- 快照不参与账本导出；换设备后不会带过去（搬家包负责）。
- 快照记录 schema 版本，恢复时走同一套迁移函数；跨大版本恢复给出提示。

### 4.5 验收

- 记 3 笔 → 等快照 → 删 1 笔 → 恢复快照，3 笔全部回来，条数与金额一致。
- 连续拍 5 次相同状态只产生 1 条；保留策略在伪造 40 条后仍只剩 30 条。
- 浏览器禁用 IndexedDB 时页面不崩、提示准确。

## 5. P0-2 加密搬家包

### 5.1 包格式

```jsonc
{
  "app": "xinshi",
  "format": "move",
  "formatVersion": 1,
  "schemaVersion": 7,
  "exportedAt": "2026-11-05T12:30:00.000Z",
  "source": { "appVersion": "0.6.0", "platform": "android" },
  "manifest": {
    "jobs": 2, "entries": 128, "restDays": 4,
    "advances": 3, "settlements": 6,
    "hours": 812.5, "entryTotal": 12345.67,
    "firstDate": "2026-06-01", "lastDate": "2026-11-05"
  },
  "checksum": "sha256:9f2c...",       // 覆盖 schemaVersion + manifest + payload
  "passwordHint": "生日后四位",        // 可选，明文
  "payload": {
    "alg": "AES-GCM",
    "kdf": "PBKDF2-SHA256",
    "iterations": 250000,
    "salt": "…", "iv": "…",
    "data": "…"                        // 密文；不加密时改为 "plain": { state }
  }
}
```

- 校验码在界面显示前 8 位（如 `9F2C8A10`），导出成功和导入预览都要显示，方便核对文件有没有传错。
- 校验和是**完整性**校验，不是签名：能发现损坏，不能阻止别人重新生成。
- `manifest` 由状态实时算出；导入解密后重新计算，对不上直接拒绝。
- 包内不写设备型号、手机号、IMEI；`source` 只有平台和 App 版本。

### 5.2 导出

- 入口：数据与安全 →「搬家到新手机」→「导出搬家包」。
- 密码可选但默认建议设：至少 6 位，两次确认，可填密码提示（明文，介意就不填）。
- 文件名：`薪时搬家包-20261105-1430.json`；Android 写入 `Download/Xinshi/`，网页下载。
- 成功提示带校验码；同一次导出可「再存一份」。

### 5.3 导入

识别矩阵：

| 文件 | 处理 |
| --- | --- |
| `format: "move"` + 加密 payload | 输入密码 → 解密 → 校验和 → 清单核对 |
| `format: "move"` + 明文 payload | 校验和 → 清单核对 |
| 旧加密备份（`encrypted: true`） | 输入密码 → 解密 → 生成 manifest → 预览 |
| 旧普通备份（`app: xinshi` + `data`） | `validateImport` → 生成 manifest → 预览 |
| 其他文件 | 明确拒绝，不写入任何数据 |

预览页必须同时展示：

```
包：2026-11-05 14:30 导出 · 校验码 9F2C8A10
    2 份工作 / 128 笔工记 / 4 天休息 / 3 笔借支 / 6 张结算单
    812.5h · 工记合计 ¥12,345.67（参考）· 2026-06-01 至 2026-11-05

本机：2 份工作 / 126 笔工记 / 4 天休息 / 3 笔借支 / 6 张结算单
    806.0h · 工记合计 ¥12,210.00（参考）

[用包覆盖本机]  [取消]
```

- 覆盖前自动拍快照，并在确认文案里写明「本机当前状态已存快照，可恢复」。
- 不做自动合并：没有删除墓碑，合并可能让已删除的工记复活、重复计薪，风险大于收益（合并排 0.6.1 评估）。
- `schemaVersion` 高于当前 App：拒绝，提示先升级；低于当前：走现有迁移，再校验。

### 5.4 新机入口

- 首次引导增加次要按钮「我是换手机，从备份恢复」。
- 恢复成功后直接进入首页，不要求再建工作。
- 空账本时，数据页显示「从搬家包恢复」大按钮。

### 5.5 验收

- 导出加密包 → 清空 → 导入，工作 / 工记 / 休息 / 借支 / 结算 / 金额 / 日期范围全部一致。
- 手改包内一个字符 → 校验失败并拒绝；密码错 → 明确提示，不写入。
- 旧版普通包、旧版加密包都能导入，预览数字正确。
- 包内清单与本机解密结果不一致时拒绝，并给出「包可能损坏」的说明。

## 6. P0-3 自动离机备份

### 6.1 平台矩阵

| 平台 | 能力 | 说明 |
| --- | --- | --- |
| Android 10+ APK | 每日自动写入 `Download/Xinshi/自动备份/` | 主动能；保留 14 份 |
| 网页（桌面 / 手机） | 自动备份不可靠，保留「到点提醒 + 一键导出」 | 不假装能自动写盘 |
| 桌面 Chrome / Edge | 0.6.1 评估 File System Access 目录授权 | 不在本版承诺 |

### 6.2 行为

- **频率**：每天最多 1 份；触发点为当日首次打开、结算成功后；失败静默重试一次。
- **命名**：`薪时自动备份-20261105.json`（日期唯一，同日重复写入覆盖同名文件）。
- **内容**：普通导出包（`app` / `version` / `data`），不带密码，导入路径与手动备份一致。
- **轮转**：只匹配前缀 `薪时自动备份-` 的文件，按修改时间保留最新 14 份；不碰用户其他文件。
- **开关**：默认关闭；用户主动开启时说明「明文写入下载目录」与保留份数；关闭后首页恢复「该备份了」提醒。
- **隐私**：界面明确写「自动备份未加密；能读手机文件的应用可能看到内容。需要保密请用加密搬家包」。
- **边界**：不打开 App 的日期不会产生备份；本地方案只能保证「打开过的那天有底」。

### 6.3 原生插件扩展

`SaveFilePlugin.java` 增加两个方法（不加权限）：

| 方法 | 作用 |
| --- | --- |
| `save({ overwrite: true })` | 同名文件直接覆盖，避免 MediaStore 生成 `(1)` 副本 |
| `prune({ prefix, keep })` | 查询 `Download/Xinshi` 下固定前缀文件，删除超出 keep 的最旧几份 |

若某些系统限制查询自己写入的文件，则退化为「写入时记录 URI 索引，按索引删除」，不影响主流程。

Android 10 以下仍只能手动导出 / 分享，按现有已知限制处理。

### 6.4 备份健康卡

数据与安全页顶部一张卡：

```
离机备份   今天 08:12 · 自动 · 14 份       [立即备份]
本机快照   12 个 · 1.2 MB / 30 MB          [管理]
账本体检   2 项提醒                        [去看看]
```

- `navigator.storage.estimate()` 有值就显示本机占用。
- 失败状态（权限被拒 / 空间不足）用黄色说明，不弹窗打断。

### 6.5 验收

- Android 14 连续模拟 20 天：目录里始终 14 份，文件名按日期正确轮转，最新一份可导入。
- 同日打开 5 次只产生 1 份；同名文件被覆盖而不是追加。
- 关闭开关后不再写文件，首页提醒恢复。
- Web 端只出现提醒，不出现「自动备份已开启」的假状态。

## 7. P0-4 账本体检

### 7.1 检查项

| # | 级别 | 检查 | 处理 |
| --- | --- | --- | --- |
| 1 | 严重 | 结算净额 ≠ 基础 + 加班 + 奖金 − 扣款 − 超休 − 借支 + 额外奖扣 | 定位到结算单，引导撤销重结 |
| 2 | 严重 | 结算纳入的工记日期超出结算周期 | 打开结算单对照 |
| 3 | 严重 | 工记 / 借支的 `settlementId` 找不到对应结算 | **一键解锁**（唯一自动修复项） |
| 4 | 严重 | 同一工记被两张结算单同时纳入 | 列出两张单，人工撤销其一 |
| 5 | 严重 | 结算周期起止颠倒 / 应发为 NaN 或负数 | 引导撤销重结 |
| 6 | 提醒 | 工记 / 结算引用的工作已不存在 | 列出来源，人工处理 |
| 7 | 提醒 | 结算引用的工记已不存在 | 提示历史数据缺口，不自动补 |
| 8 | 提醒 | 同一工作同一天既有工记又有休息 | 二选一 |
| 9 | 提醒 | 同一工作同一天多条工记 | 并排对比 |
| 10 | 提醒 | 同一天多份工作合计 > 24h | 提示核对 |
| 11 | 提醒 | 休息天数不是 0.5 / 1 | 人工确认 |
| 12 | 提醒 | 已收金额 > 应发净额 | 打开收款登记 |
| 13 | 提醒 | 超休扣款 > 当月固定月薪 | 打开结算设置 |
| 14 | 提示 | 未来日期工记（计划补记）、超过 2 个周期未结、空工作、备份过期 | 只提示，不算错 |

### 7.2 修复原则

- **绝不自动改金额**。
- 自动修复只有第 3 项：清除指向不存在结算的锁定，让记录重新参与计算；修复前拍快照，Toast 可撤销。
- 其余项提供「去处理」入口，跳到对应页面并高亮目标；处理后回到体检页自动重算。
- 级别定义：严重 = 金额可能算错；提醒 = 可能录错，需要人看一眼；提示 = 正常但值得知道。
- 规则保守：未来工记、固定月薪休息日、跨岗位同日多笔都不算错误。

### 7.3 入口与时机

- 数据与安全页「账本体检」；首页备份横幅下方显示一行「体检发现 2 项提醒」。
- 打开体检页时实时计算（万条记录目标 < 1s），不写入账本。
- 导入搬家包后自动跑一次体检；有问题在成功提示里带一句。

### 7.4 验收

- 构造 14 类问题各一条，体检全部命中，正常样例 0 误报。
- 第 3 项一键修复后记录解锁、可重新结算；撤销恢复锁定。
- 体检页在 320px、深色模式下不横向溢出；从体检跳到目标页再返回，结果刷新。

## 8. P0-5 Excel 对账表

### 8.1 四张表

| Sheet | 列（摘要） |
| --- | --- |
| `工记明细` | 日期、星期、工作、雇主、开始、结束、休息(分)、工时、加班工时、计件数量、单价、基础工资、加班工资、奖金、扣款、合计、节假日、结算状态、单号、备注 |
| `月度汇总` | 月份、工作、出勤天数、休息天数、工时、加班工时、基础、加班费、奖金、扣款、超休扣款、借支抵扣、应发、状态（已结 / 未结预估） |
| `结算单` | 周期开始、结束、工作、基础、加班、奖金、扣款、超休、借支抵扣、额外奖、额外扣、应发、已收、待收、收款状态、备注 |
| `借支` | 日期、工作、金额、是否已抵扣、结算周期、备注 |

- 金额两位小数、工时最多一位；首行冻结 + 自动筛选；列宽按内容预设。
- 汇总口径必须与 App 一致：月薪封顶用现有 `sumEntriesCapped` / 结算草稿函数，不另写一套算法；已结周期以结算快照为准。
- 文件名：`薪时账本-20261105.xlsx`；Android 写入 `Download/Xinshi/`，网页下载。
- 入口：数据与安全 →「Excel 对账表」；记录页也可放一个快捷入口。

### 8.2 实现

- 自研 `src/lib/xlsx.ts`（约 300 行）：ZIP（DEFLATE 优先，`CompressionStream('deflate-raw')`，不支持则 store）+ CRC32 + XML。
- 样式只做数字格式（`0.00` / `0.0`）与首行加粗，不引 UI 主题色。
- 中文用 `inlineStr`，避免 sharedStrings 复杂度；sheet 名 ≤ 31 字符。
- **不新增前端依赖**；如自研在 WPS 上出现兼容问题，备选方案是引入 SheetJS（需在实现时记录决策）。

### 8.3 验收

### 14.2 关键实现点

- 快照压缩、哈希、IndexedDB 全部异步，页面首屏不等待。
- 搬家包加解密复用 `backup.ts` 的 PBKDF2 / AES-GCM 参数，避免两套安全参数。
- 校验和用 WebCrypto SHA-256；不支持的旧 WebView 降级为 FNV-1a 并标注「弱校验」。
- Excel 的 DEFLATE 用 `CompressionStream`，不支持时 ZIP 用 store（文件变大但能打开）；CRC32 自实现，查表。
- 体检为纯函数 `checkLedger(state): Issue[]`，修复为 `applySafeFixes(state, issueIds)`，两者都可单测。
- 自动备份调度只在原生 Android 生效；Web 端不注册定时器写文件。
- 隐私同意按版本号记录，政策更新后重新弹窗；Android release 清单去掉 INTERNET，`allowBackup=false`，targetSdk 36。

**没有服务器怎么多端**（发布后写进 README）：

1. **微信 / QQ 文件传输**：导出搬家包发给自己，另一台手机导入。
2. **网盘文件夹**：把 `Download/Xinshi` 设为自动同步目录（坚果云 / OneDrive 等）。
3. **Syncthing / FolderSync**：两台 Android 互相同步备份目录，需要时在 App 里用系统文件选择器导入。
4. **电脑中转**：数据线拷出，换机时再拷回。

共同约束：不做实时同步；导入是替换；两台设备都改过时，先导出再人工选择。

1. **自动备份默认关闭**：按上架隐私优先的原则，改为用户主动开启；开启时明确提示明文风险。
