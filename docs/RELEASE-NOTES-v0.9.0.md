# 薪时 v0.9.0 发布说明

> 版本：**0.9.0** ｜ versionCode：**900** ｜ 发布日期：**2026-11-06**
>
> 主题：**删了也能找回**
>
> 一句话：工记、休息、借支和工作统一进回收站，30 天内可恢复；同时修掉审计发现的
> 数据导入、删除保护与弹层焦点问题。

---

## 1. 本次更新亮点

### 1.1 统一回收站

以前只有「空工作」会进回收站，工记 / 休息 / 借支删除后只有 5 秒撤销。v0.9.0 把四类记录统一收进回收站：

- **四类记录**：工记、休息、借支、工作。
- **保留规则**：每类保留 **30 天**、最多 **120 条**，超期或超量自动清理。
- **筛选与汇总**：全部 / 工记 / 休息 / 借支 / 工作；显示待处理条数、涉及金额、工时、休息天数。
- **恢复**：恢复到原日期、原工作，恢复前先校验。
- **彻底删除**：单条确认删除，或一键清空回收站。
- **入口**：我的 → 数据 → 回收站；工作管理 → 回收站（有记录时显示总数）。

### 1.2 恢复前给出具体原因

恢复不再只提示「恢复失败」，而是说明为什么不能恢复：

- 原工作已彻底删除；
- 原工作还在回收站，需要先恢复工作；
- 这段时间已结算，需要先撤销结算；
- 恢复后同一天合计会超过 24 小时；
- 这天已有工记，休息和工记只能留一个。

### 1.3 删除保护

有工记、借支、休息或结算记录的工作**只能归档，不能彻底删除**。
以前删除有休息日的工作会静默连休息日一起清掉，现在会直接拦截；
彻底删除工作时，也会级联清理指向它的回收站副本，避免留下无法恢复的死数据。

### 1.4 导入与数据安全

- 备份里的回收站记录会一起导入，并按 30 天 / 120 条规则清理。
- 回收站记录可以指向仍在回收站里的工作，不再导致整份备份被拒绝。
- 坏掉的单条回收站记录会跳过，不会因为一条旧数据拒绝整包。
- 导入时拒绝重复的工记 / 借支 / 结算 ID，避免后续编辑或删除命中多条记录。
- 数据仍是 **schema v7**，旧备份、搬家包、本机快照继续兼容。

### 1.5 弹层焦点与键盘

- 抽屉 / 确认框打开后自动聚焦，Tab 在弹层内部循环，关闭后焦点归还给触发按钮。
- 确认框叠在抽屉上时，按 Esc 只关闭最上面的确认框，不会连抽屉一起关掉。

### 1.6 版本与构建

- 关于页 / 引导页 / 页脚统一显示 **v0.9.0**，版本号仍只从 `package.json` 注入。
- Android `versionCode 900` / `versionName 0.9.0`；Service Worker 缓存升级到 **v23**。
- 权限不变：仍只有通知、开机恢复提醒、WakeLock，**不申请 INTERNET**。

## 3. 升级与兼容

- **覆盖升级**：同签名可直接从 v0.8.0 覆盖安装，账本数据保留。
- **数据格式**：仍是 `xinshi.state.v7`，新增字段为可选数组；旧备份缺省为空，不要求迁移。
- **新备份在旧版本**：v0.8.0 打开 v0.9.0 导出的备份时会忽略回收站数组，主账本仍可导入。
- **debug / release 签名不同**：从旧 debug 包切到正式包需要先卸载；卸载会清空本机数据，请先导出备份。
- **建议**：升级前在「我的 → 数据与安全」导出一次备份。

## 7. 已知限制

- **未重跑 0.9.0 真机**：原生壳与 v0.8.0 一致；本版验证覆盖构建、权限、浏览器场景与分辨率矩阵。
- **回收站不分页**：受每类 120 条上限约束，最多 480 行；暂不支持按工作筛选或分页。
- **恢复限制**：原工作被彻底删除、周期已结算、同日超过 24 小时、休息与工记冲突时不能恢复。
- **记工覆盖休息**：同岗位同一天记工后，原有休息标记会被移除且不进回收站；这是互斥规则的副作用。
- **回收站只在本机**：不随备份之外的方式同步；换设备请使用搬家包 / 导出导入。
- **彻底删除不可逆**：回收站里的单条删除和清空操作都会永久移除数据。
- **计薪规则未变**：本版不调整任何工资算法，历史金额不受影响。
- 计薪结果仅供参考，不构成劳动、税务或法律意见。
