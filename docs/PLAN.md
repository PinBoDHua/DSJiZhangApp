## 1. 产品判断

### 1.1 要解决的问题

短期工、日结工、小时工、周结工、长期月结工，算工资的方式各不相同，但共同痛点是：

1. **记不清**：干了几天、几个小时、加了多少班，靠脑子记、靠微信收藏，月底对不上。
2. **算不明**：时薪 × 工时、日薪、月薪折算、加班倍率、借支抵扣，混在一起容易算错。
3. **说不清**：结账时拿不出明细，和工头 / 老板扯皮没有依据。
4. **工具不贴合**：通用记账 App 只记金额，不记工时；考勤 App 面向公司，不适合个人；Excel 门槛高、手机上难用。

### 1.2 产品定位

**个人侧、离线优先的轻量记工工具**，不是 HR 考勤系统，也不是招聘或支付平台。

- 面向：个人劳动者（也适合小工头替自己记工）。
- 核心闭环：**记工 → 算钱 → 对账 → 结算 → 留存**。
- 差异点：把「工时 / 出勤 / 加班 / 借支 / 结算周期」放在一个模型里算清楚，并用一张能看懂的结算单收尾。

### 1.3 MVP 原则

- **先算对，再好看**：所有金额都能展开看到公式，宁可不做，不做错。
- **3 秒记一笔**：默认值合理，常用路径不超 3 次点击。
- **不登录、不联网也能用**：数据只存本机，降低使用门槛与隐私顾虑。
- **移动端优先**：按 390px 宽度设计，桌面端居中呈现。
- **范围克制**：只做个人记工闭环，不做账号、云同步、雇主端、支付。

## 2. 用户与场景

| 人群 | 典型计薪 | 结算 | 最关心 | 典型场景 |
| --- | --- | --- | --- | --- |
| 小时工 / 兼职 | 时薪 × 工时，可能含加班 | 日结 / 周结 | 今天几小时、这周多少钱 | 门店兼职、分拣、家政、活动执行 |
| 短期日结工 | 日薪，干一天算一天 | 日结 / 周结 | 出了几天工、有没有被少算 | 工地、装修、搬运、展会 |
| 周结工 | 时薪或日薪，按周汇总 | 周结 | 本周总工时、周末加班倍率 | 工厂临时线、餐饮旺季 |
| 长期月结工 | 月薪，加班另算 | 月结 | 出勤、加班费、借支后到手 | 工厂、物业、长期工地 |
| 多份零工 | 混合 | 混合 | 每份工作分别欠多少 | 同时跑两三个地方 |

### 2.1 核心用户故事（MVP 必须成立）

1. 作为小时工，我下班后花 10 秒记下「今天 8:00–17:30，休息 30 分钟」，App 自动算 9 小时、基础工资和超时加班费。
2. 作为日结工，我选「出勤一天」就能记账，不用填时间；有额外加班时再补加班小时。
3. 作为月结工，我能看到本月出勤、加班费、借支，月底生成一张结算单，知道实际到手多少。
4. 作为同时打两份工的人，我能给每份工作设不同的计薪方式与结算周期，互不干扰。
5. 结算后记录被锁定，避免误改；发现错了可以在历史结算里撤销重来。
6. 换手机 / 清缓存前，我能导出备份；到新设备导入后数据完整回来。

### 2.2 非目标用户（本版不做）

公司 HR、需要批量排班 / 审批的团队、需要发薪 / 代缴社保的机构、需要对接考勤机的场景。

## 4. 计薪与结算规则（核心）

> 所有金额以人民币元为单位，内部按「分」四舍五入（`round2`），逐项计算后再汇总，避免浮点误差累积。
> 每条记录在创建时**冻结当时的计薪规则快照**（单价、标准工时、倍率、计薪天数），之后修改工作单价不影响历史记录。

### 4.1 基础参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 标准工时 / 天 | 8 小时 | 超过部分默认计为加班（仅小时工时自动拆分） |
| 月计薪天数 | 22 天 | 月薪折算日薪使用，可改 |
| 平日加班倍率 | 1.5 | 可改 |
| 休息日（周六日）加班倍率 | 2.0 | 可改，按日期自动判断 |
| 法定节假日加班倍率 | 3.0 | 可改，记录上手动勾选 |
| 周起始日 | 周一 | 可在「我的」中改为周日 |

### 4.2 三种计薪方式

#### A. 时薪（hourly）

- 工时 = 结束时间 − 开始时间 − 休息时长；跨零点自动加 24 小时。
- 若开启「加班另算」：加班工时 = max(0, 总工时 − 标准工时)，自动计算、不可手改。
- 基础工资 = (总工时 − 加班工时) × 时薪
- 加班工资 = 加班工时 × 时薪 × 倍率
- 若关闭加班：全部工时 × 时薪。

**例**：时薪 25，8:00–17:30，休息 30 分钟 → 9h；标准 8h，平日 1.5 倍 → 基础 8×25=200，加班 1×25×1.5=37.5，合计 **¥237.50**。

#### B. 日薪（daily）

- 每条记录代表出勤 1 天，基础工资 = 日薪。
- 加班工时为手填（选填）；开启加班才可填。
- 加班时薪 = 日薪 ÷ 标准工时 × 倍率
- 合计 = 日薪 + 加班工时 × 加班时薪 + 奖金 − 扣款。

**例**：日薪 320，标准 8h，平日加班 1h（1.5 倍）→ 320 + 60 = **¥380.00**。

#### C. 月薪（monthly）

- 每条记录代表出勤 1 天，日折算 = 月薪 ÷ 月计薪天数（用于记录级展示与估算）。
- 加班时薪 = 月薪 ÷ 月计薪天数 ÷ 标准工时 × 倍率。
- **结算时按月封顶**：当月结算基础工资 = round2(月薪 ÷ 月计薪天数 × 当月出勤天数)，且不超过整月月薪。避免 23 天出勤把月薪算超；按整月汇总后再四舍五入，保证 10 天场景是 7500 ÷ 22 × 10 = **¥3,409.09**。
- 月薪工作固定按月结算；月中入职 / 离职等特殊情况，用结算页的「额外奖扣」调整。
- 固定月薪的休息规则分两种：**固定额度**（默认，超出额度可选扣款）和 **随机休息**（不设额度，休息日按日期留痕，不扣固定月薪）。
- 月结页会列出本期每天是「出勤 / 休息 / 未记」，并允许在确认结算前补标或取消休息；具体日期会写进结算快照。

**例**：月薪 7500，月计薪 22 天，当月出勤 10 天 → 7500 ÷ 22 × 10 = **¥3,409.09**（结算时四舍五入）。

### 4.3 加班倍率判定

优先级：**法定节假日（手动勾选，3x） > 周六日（自动，2x） > 平日（1.5x）**。
加班倍率只在「开启加班另算」时生效；关闭后不产生加班费，所有工时按基础单价计。

### 4.4 结算规则

对某份工作、某个结算周期：

```
基础工资 = Σ 各记录基础工资（月薪工作按月封顶）
加班工资 = Σ 各记录加班工资
奖金     = Σ 各记录奖金 + 结算额外奖金
扣款     = Σ 各记录扣款 + 结算额外扣款
借支抵扣 = 该工作所有「未抵扣且日期 ≤ 周期结束日」的借支
应发净额 = 基础工资 + 加班工资 + 奖金 − 扣款 − 借支抵扣
```

- 只纳入**未结算**的记录；已结算记录不会重复计入。
- 借支是「已经拿到的钱」，不是额外收入，因此在结算时抵扣。
- 确认结算后生成**快照**（金额、记录 ID、借支 ID、周期），记录与借支被锁定。
- 撤销结算：删除快照并解锁记录 / 借支，金额重新参与下一轮计算。
- 已锁定的记录不允许直接编辑 / 删除，需先撤销对应结算（UI 明确提示）。

### 4.5 周期定义

| 周期 | 区间 | 说明 |
| --- | --- | --- |
| 日结 | 当天 00:00–23:59 | 按记录日期 |
| 周结 | 周起始日 起 7 天 | 默认周一到周日，可改为周日到周六 |
| 月结 | 自然月 1 日–月末 | 月薪工作固定月结 |

### 4.6 边界与取舍

- **时薪 + 跨天**：下班时间早于上班时间视为跨零点，工时正确计算，记录归上班当天。
- **休息时长**：仅时薪的上下班模式使用；不能超过在岗时长，表单校验。
- **月薪封顶**：结算时按「该月记录中的最新单价」作为封顶值；月中调薪属极少数情况，文档与界面注明。
- **一周跨月**：周结按记录日期归周，结算单显示实际日期区间，不做拆分。
- **手改金额**：MVP 不直接改「应发净额」，只提供额外奖金 / 扣款调整，保证账目可解释。
- **免责声明**：结果仅作个人记账参考，不构成法律或税务依据；各地加班法规差异需用户自行确认。

### 5.3 关键交互

- **记一笔**：底部全屏抽屉；工作 chips 一键切换；今天 / 昨天 / 前天快捷日期；小时工支持「时间区间」与「直接填工时」两种模式；底部固定实时工资预览。
- **金额隐私**：首页眼睛图标一键隐藏金额，状态持久化。
- **结算确认**：二次确认弹层展示应发净额与「结算后锁定」提示。
- **撤销结算**：历史详情内危险操作，二次确认。
- **删除记录**：详情内二次确认；已结算记录禁用并提示先撤销结算。

## 11. 风险与决策记录

### 11.1 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 月薪折算规则因公司而异 | 金额争议 | 公式透明、月计薪天数可调、结算可加额外奖扣、注明仅供参考 |
| 用户不信任自动计算 | 弃用 | 每笔可展开明细；修改规则只影响未来；结算单可复制留证 |
| 本地数据丢失 / 清缓存 | 数据不可恢复 | 显眼的数据备份入口；导出文件带版本号；后续做自动备份提醒 |
| 浏览器存储被回收 | 长期数据风险 | 引导安装 PWA；自动离机备份 + 加密搬家包（v0.6.0）；导出提醒 |
| 范围膨胀 | 延期 | P0 清单冻结；新想法一律进 P1 / 路线图 |
| 加班法规地域差异 | 误导 | 不提供合规判断，倍率完全可配置，文案明确免责 |

### 11.2 关键决策

1. **不做账号，本地优先**：MVP 最快闭环，隐私友好；代价是多设备要手动导入导出。v0.6.0 用「加密搬家包 + 自动备份 + 第三方文件同步」替代云同步，不引入服务器。
2. **计薪快照写入每条记录**：保证历史金额不随调价变化，这是「可信」的底线。
3. **结算 = 快照 + 锁定 + 可撤销**：既防误改，又保留纠错路径；比「只读汇总」更符合真实对账。
4. **月薪按日折算、按月封顶**：兼顾展示直观与总额正确；月中调薪等边角情况用额外奖扣兜底。
5. **结算单不直接手改净额**：只允许额外奖金 / 扣款，保证每一分钱都有来源。
6. **移动端优先的单栏布局**：目标用户主要在手机上使用；桌面居中即可，不做独立后台。
7. **不引图表库 / UI 框架**：控制体积与视觉一致性，SVG 柱状图足够 MVP。

### 13.3 相对规划的补充
