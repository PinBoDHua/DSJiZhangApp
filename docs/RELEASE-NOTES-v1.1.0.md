# 薪时 v1.1.0 发布说明

> 版本：**1.1.0** ｜ versionCode：**1100** ｜ 发布日期：**2026-11-07**
>
> 主题：**看得清 · 一本清楚账**
>
> 一句话：把首页、工记、结算、统计的版面按「记工账本」重排，让本月收入、今天记了什么、
> 每一笔工钱一眼可查；同时修掉 1.0 遗留的日薪重复计费、固定月薪非自然月多发、
> 结算连点重复、快照误报成功、导入引用不一致、通知重排丢提醒与 WebView 反复崩溃。
> 数据格式仍是 **schema v7**，旧备份继续可导入，已生成的结算单不受影响。

---

## 1. 本次更新亮点

### 1.1 首页改版

- 顶部由问候语改为「**XX 的记工账本**」（示例数据为「李师傅的记工账本」），品牌区副标改为「记工账本」。
- 收入卡重排：标题改「本月预计收入」，右上角新增「明细 →」直达工记页，金额下方直接显示
  「已记 X 天 · 休 X/Y 天」与待结金额，底部三列指标为**本月工时 / 出勤 / 加班**。
- 「**最近明细**」整块前移到收入卡下方，带「全部明细 →」；空账本时给出「记第一笔」引导。
- 「今天已记」卡片保留计时 / 休 / 再记三个入口，与新的信息层级对齐。

### 1.2 工记页改版

- 标题改「**工记明细**」，副标「按月核对工时与收入」，动作只保留搜索与「记一笔」。
- 原散落在标题栏的图标按钮收进工具栏：**列表 / 日历视图**、**月度考勤**、**记休息**，
  每个按钮带文字标签，不再只靠图标猜。
- 月份切换、收入合计卡（收入 / 出勤 / 工时 / 加班 / 本月另休）与按日分组保持一致；
  固定月薪单笔金额标注「固定月薪」，并在汇总卡说明「按整月发放」。

### 1.3 结算、统计与引导表述

- 结算页：「工资结算 · 应结、已收、待收，一笔不漏」；统计页：「工资统计 · 看清工时与收入」。
- 引导页主标题改为「**记工算薪，一本清楚账**」，副文案改为「干完活记一笔，自动算工钱；
  到结算日，应得多少、已收多少，一看就明白」。
- 记一笔的金额提示：固定月薪从「月薪内 / 固定月薪整月发放」改为
  「**当日折算参考 / 固定月薪，此处金额仅作参考**」，避免把折算值当成当月实发。

### 1.4 视觉系统

- 配色从暖纸色转为冷白底色 + 深松绿主色：`--paper #f4f6f5`、`--surface #ffffff`、
  `--primary #146b4b`（原 `#0e5238` / 页面底 `#f6f2e9`），移除页面背景的两层径向渐变。
- 圆角 `22px → 18px`，阴影收敛；新增 `--text-xs … --text-amount(46px)` 字号变量，
  金额用大数字表达。
- Logo 表盘改为白色，Wordmark 副标「XINSHI → 记工账本」；`theme-color` / PWA manifest /
  深浅色主题同步到新主色。
- 深色主题跟随同一套 tokens，不额外维护第二套色值。

### 1.5 计薪口径修正

- **日薪同日去重**：同一工作同一天的多段记工，只计一次日薪基数，加班 / 奖金 / 扣款仍逐笔累加。
  汇总卡、日收入曲线、12 周热力图、年度统计、快照清单统一使用同一口径。
- **固定月薪非自然月折算**：结算周期不是完整自然月（周结 / 日结 / 跨月）时，固定月薪按
  「月薪 ÷ 计薪天数 × 实际出勤天数」折算并封顶；整月周期仍发全额，不改变长期工习惯。
- **加班时长上限**：所有计薪类型的加班小时都限制在当日工时内（此前只有时薪受限）。
- **金额舍入**：合计金额由已舍入的基础工资与加班费相加，分项与合计不再差 1 分。
- **超休扣款日薪**：固定月薪的超休扣款默认日薪改用该岗位**历史工记规则**，
  调价后重算旧周期不会按新单价扣。

### 1.6 结算原子提交

- 新增纯函数 `commitSettlement`：校验岗位存在、周期不重叠、周期内有工记后，
  一次性产出「结算单 + 锁定工记 + 绑定借支」的新状态，不修改入参。
- Store 提交后同步推进 `stateRef`，同一渲染周期内连续点击「确认结算」只生成一张结算单，
  不会出现两张结算或只锁一半记录。
- 本机快照写入改为等待 IndexedDB 事务 `oncomplete`，`error` / `abort` 都会让保存失败，
  不再出现「提示已保存、实际没写进去」。

### 1.7 导入校验

- 日期按真实日历校验：`2026-02-30`、`2026-13-01`、平年 2 月 29 日一律拒绝，闰年 2 月 29 日放行。
- 结算周期开始日期不得晚于结束日期。
- 结算单与工记 / 借支必须是**双向引用**：结算单列出的每条记录都要指回这张结算单，
  记录的 `settlementId` 也必须在结算单里；岗位必须一致；工记日期必须落在周期内，
  借支允许早于周期（上期结转）但不允许晚于期末。
- 单向引用不再被静默修复为正常数据，主动导入同样拒绝。

### 1.8 提醒与自动备份

- 每日记工提醒与发薪通知改为「**先排新计划、成功后再清理旧提醒**」；
  调度失败时保留旧提醒，不会出现「旧的已取消、新的没排上」。
- 自动备份文件名追加时分秒（`薪时自动备份-20261107-193012.json`），同一天多次备份不再互相覆盖。
- 原生保存增加 **32MB 上限**，超过时直接提示，避免大文件把内存撑爆。

### 1.9 Android 壳

- **渲染进程崩溃恢复**：`onRenderProcessGone` 时先销毁 WebView 再 `recreate()` 重建 Activity，
  不再对已经死掉的 WebView 调 `reload()`；页面稳定 30 秒后清零崩溃计数，
  只有 30 秒内连续崩溃才进入崩溃页。
- **文件保存**：去掉「同名覆盖」分支，MediaStore 查询改为
  `display_name = ? AND relative_path = ? AND owner_package_name = ? AND is_pending = 0`，
  相对路径统一带结尾斜杠；写入后发布失败立即删除半成品，不留下 0 字节文件。
- **诊断导出**：同样按精确文件名 + 路径 + owner 匹配，`update` 失败时清理残留。

### 1.10 版本与构建

- 关于页 / 引导页 / 页脚统一显示 **v1.1.0**，版本号仍只从 `package.json` 注入。
- Android `versionCode 1100` / `versionName 1.1.0`；Service Worker 缓存升级到 **v25**。
- 权限不变：仍只有通知、开机恢复提醒、WakeLock，**不申请 INTERNET / CAMERA**。
- 数据格式不变：仍是 `xinshi.state.v7`，没有新增字段。

## 2. 修复清单

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P0 | 同岗位同日多段记工重复计日薪基数 | 按 `jobId + date` 只计一次基础工资，汇总 / 日曲线 / 热力图 / 年度 / 快照统一 |
| P0 | 固定月薪在周结 / 日结 / 跨月周期按整月封顶，多发工资 | 非自然月按出勤折算并封顶，整月仍发全额 |
| P0 | 结算提交先读旧 state 再写，连点可能生成两张结算 | `commitSettlement` 原子提交 + 同步 `stateRef` |
| P0 | 快照 `put` 成功即返回，事务失败仍报成功 | 等事务 `oncomplete`，`error` / `abort` 均拒绝 |
| P1 | 导入接受 `2026-02-30` 这类伪日期 | 真实日历校验（大小月 / 闰年） |
| P1 | 导入可带结算与工记 / 借支单向引用或跨岗位 | 双向引用 + 岗位 + 周期校验，一律拒绝 |
| P1 | 每日提醒 / 发薪通知先清旧再排新，排新失败等于没有提醒 | 先排后清，失败保留旧提醒 |
| P1 | 自动备份同日覆盖，只剩最后一份 | 文件名带时分秒 + 不再覆盖写入 |
| P1 | WebView 渲染进程崩溃后 `reload()` 复用死进程 | 销毁 WebView + 重建 Activity，30 秒稳定后清零计数 |
| P1 | 加班小时可超过当日总工时（日薪 / 月薪 / 计件） | 统一 clamp 到当日工时 |
| P2 | 导出诊断文件按 `LIKE 前缀%` 匹配，可能覆盖同前缀文件 | 精确文件名 + 路径 + owner 匹配 |
| P2 | 保存文件发布失败留下 0 字节半成品 | `update` 失败即删除该 MediaStore 行 |
| P2 | 超休扣款日薪跟随当前工作设置，调价后旧周期算错 | 使用该周期历史工记规则 |
| P2 | 合计金额与分项之和差 1 分 | 合计由已舍入分项相加 |

## 3. 升级与兼容

- **覆盖升级**：同签名可直接从 v1.0.0 覆盖安装，账本数据保留。
- **数据格式**：仍是 `xinshi.state.v7`，本版不新增任何字段；旧备份 / 搬家包 / 本机快照继续可用。
- **已生成结算单不变**：结算单是锁定的快照，本版的计薪口径修正只影响未结工记的重算结果。
- **金额可能变化的两处**（符合预期，不是数据损坏）：
  1. 同一工作同一天记了多笔时，日薪基数只算一次，未结金额会比 1.0.0 低；
  2. 固定月薪的周期不是完整自然月时，按出勤折算，不再按整月计。
- **建议**：升级前在「我的 → 数据与安全」导出一次备份。

## 7. 已知限制

- **渲染进程恢复未做压测**：只验证了「单次崩溃 → 销毁并重建页面」这一条路径（真机截图见 `shots/android-v080/09-renderer-recovered.png`），没有连续崩溃 / 低内存 / 多次重建的压测；30 秒内再次崩溃会进入原生崩溃页，而不是无限重建。
- **AAB 未出**：本版只有签名 APK；上架前需补 `bundleRelease` 并校验签名。
- **计薪口径变化**：日薪同日多段、固定月薪非整月折算会改变未结金额；如与历史口头约定不一致，请在结算「额外奖扣」里调整。
- **月薪折算仍是展示口径**：记一笔里的「当日折算参考」不是当月实发，固定月薪仍以整月结算为准。
- **通知仍受系统限制**：未申请精确闹钟权限，Doze / 省电模式可能延迟；提醒计划仍是 30 天滚动续排。
- **自动备份文件名变长**：带时分秒后同日多份，保留策略仍是最近 14 份；清理依赖 MediaStore 前缀匹配。
- **32MB 上限**：超过时直接拒绝保存，需要改用导出 / 分享面板的路径。
- **视觉重排未做桌面双栏**：仍是手机优先单栏，≥720px 只调整留白与字号。
- **深色主题**：跟随新 tokens 整体调色，历史截图与 v1.0.0 不一致属预期。
- 计薪结果仅供参考，不构成劳动、税务或法律意见。
