# 薪时云同步设计（v0.4 候选）

> 状态：设计稿，未实现 ｜ 目标：可选账号 + 多设备同步，不破坏本地优先
>
> 本文只解决「如果要做云同步，应该怎么做」。v0.3 不包含登录、服务器和上传逻辑。

---

## 1. 目标与非目标

### 目标

- 不登录也能完整使用本地账本。
- 登录是**可选增强**，开启后才上传。
- 同一账号多设备看到一致的工作、工记、借支、结算。
- 冲突可解释、可选择，不静默丢数据。
- 支持导出全部数据、注销账号、删除云端数据。
- 工资数据在传输和存储上都受保护。

### 非目标

- 不做社交、招聘、支付、社保代缴。
- 不做多人协作 / 工头端（后续版本）。
- 不做 CRDT 级实时协同；MVP 用「版本号 + 冲突提示」。
- 不承诺免费公共托管；先支持自托管和单实例托管。

---

## 2. 两种落地方式

### A. 自托管（推荐作为第一步）

```
手机 PWA ──HTTPS──> Node/Fastify 服务 ──> SQLite / PostgreSQL
                         │
                         └── 定时备份到对象存储
```

- 仓库增加 `server/`，`docker compose up` 即可。
- 用户/小团队可以部署到 VPS、NAS、Railway、Render。
- 优点：数据可控、成本低、容易做端到端加密。
- 缺点：普通用户没有服务器，需要提供部署文档或代部署。

### B. 托管服务

- Supabase / Cloudflare D1 + Workers / 自建云。
- 优点：开箱即用。
- 缺点：账号、隐私政策、数据合规、备份、客服都要长期负责。
- 建议等自托管验证需求后再做。

## 3. 推荐架构（自托管 MVP）

### 3.1 服务端

- Node 22 + Fastify（或原生 http，减少依赖）。
- SQLite（单实例，WAL 模式），表：
  - `users(id, login, password_hash, created_at, deleted_at)`
  - `sessions(id, user_id, token_hash, expires_at, created_at)`
  - `sync_states(user_id, revision, ciphertext, updated_at)`
  - `audit_log(id, user_id, action, created_at)`（不记录工资内容）
- 密码：Argon2id（或 scrypt），每用户独立 salt。
- 会话：随机 32 字节 token，服务端只存 hash；HttpOnly / Secure / SameSite=Lax（若用 Cookie）。
- 限流：登录 5 次/分钟/IP；同步 60 次/分钟/用户。
- 强制 HTTPS；反向代理终止 TLS。

### 3.2 客户端

- 保留 `localStorage` 为唯一事实源；同步是后台镜像。
- 设置页新增「云同步（可选）」：
  - 服务器地址；
  - 登录 / 注册；
  - 同步密码（用于客户端加密，可与登录密码不同）；
  - 最近同步时间、状态、手动同步、退出登录。
- 未开启时，所有现有功能完全不变。
- 同步失败不阻塞记工；显示「待同步」状态，下次重试。

### 3.3 端到端加密（推荐）

```
state JSON
  → gzip
  → AES-256-GCM（密钥由同步密码 + PBKDF2/Argon2 派生）
  → base64 密文
  → 上传
```

- 服务端只保存密文，无法读取工作名、金额。
- 同步密码不发送服务器；忘记后无法解密云端数据（但本地仍有数据）。
- 代价：服务端无法做字段级合并、搜索、客服找回。
- v0.4 先做「整包加密快照」，不做字段级 CRDT。

## 4. 同步协议（MVP）

### 4.1 认证

```
POST /api/auth/register  { login, password }
POST /api/auth/login     { login, password } -> { token, expiresAt }
POST /api/auth/logout
GET  /api/me
DELETE /api/account      { password }  // 软删 + 30 天后硬删
```

### 4.2 拉取 / 推送

```
GET  /api/sync
  -> 200 { revision, ciphertext, updatedAt }
  -> 404 尚无云端数据

PUT  /api/sync
  { baseRevision, ciphertext }
  -> 200 { revision, updatedAt }
  -> 409 { currentRevision }   // 云端已更新
```

- `baseRevision` 必须等于云端当前版本，否则 409。
- 409 时客户端展示：
  - 云端更新时间 / 本机更新时间；
  - 「用云端覆盖本机」/「用本机覆盖云端」/「先导出再决定」；
  - 不自动合并。
- 首次开启：
  - 云端为空 → 上传本机；
  - 云端有数据、本机为空 → 下载；
  - 两边都有 → 让用户选择，不静默覆盖。
- 自动同步：本地状态变化后 3 秒防抖；页面回到前台时拉取；失败指数退避。

### 4.3 版本与设备

- 服务端 `revision` 单调递增，不依赖客户端时间。
- 客户端保存 `lastSyncedRevision` 和 `lastSyncedAt`。
- 同一账号多设备同时改：后提交者 409，人工选择。
- 不做「按工记合并」：ID 冲突、删除语义、结算锁定跨设备很难在 MVP 里保证正确。

## 5. 数据迁移

- 本地 v3 → 账号：上传现有 state 的加密快照；本地数据不删除。
- 账号 → 新设备：登录、拉取、解密、`validateImport` 校验，再替换本地。
- 已有本地数据 + 云端数据：必须选择，不能自动覆盖。
- 退出登录：保留本地数据，删除本机会话 token。
- 注销账号：服务端删除密文；本地数据保留，除非用户另行清空。

---

## 6. 安全与隐私清单

- TLS 1.2+，HSTS；拒绝明文 HTTP（localhost 除外）。
- 密码哈希使用 Argon2id；禁止明文/可逆存储。
- 会话 token 只存 hash；支持全部设备登出。
- 同步密文使用 AEAD；服务端不接触同步密码。
- 日志不记录请求体、工资、工作名；只记录状态码、耗时、用户 ID 哈希。
- 备份数据库加密；定期恢复演练。
- 速率限制、CORS 白名单、请求体大小限制（如 5 MB）。
- 隐私政策、数据导出、账号注销、数据删除时限。
- 不以「云同步」为默认开启；首次开启必须明确告知上传内容。

## 8. 本版决策

- **v0.3 不实现云同步**：没有可托管的账号后端，做半成品登录会误导用户。
- 先完成计件、PDF、加密备份、备份提醒，把本地账本做可信。
- 云同步按本文档在 v0.4 单独立项；优先自托管 + 端到端加密。
