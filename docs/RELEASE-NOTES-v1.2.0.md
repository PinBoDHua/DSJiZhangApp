# 薪时 v1.2.0 发布说明

## 本版定位

v1.2.0 在不引入账号、服务器和网络权限的前提下，补齐分类统计、月度预算提醒、完整工记导出与周期记工，并对现有数据层、原生桥接和统计口径做了一轮系统审计修复。

项目仍是本地优先的记工算薪 App：没有独立服务器后端；网页状态层与 Android 原生文件 / 通知插件之间的接口均纳入本次检查。

## 新增功能

### 1. 分类统计

- 统计页新增按时薪、日薪、月薪、计件分类的收入分布。
- 显示金额、占比、工记笔数、出勤日期数和工时。
- 月薪继续按「岗位 × 自然月」处理，多个工作或多个月不会错误合并封顶。
- 同月发生调价时按每天保存的计薪快照折算，不用月末新价回写历史。

### 2. 月度预算提醒

- 「我的 → 提醒 → 月度预算提醒」可设置本月收入目标和工时上限。
- 两项可独立使用；至少一项大于 0 才能开启。
- 达到 80% 时提示接近目标 / 上限，达到 100% 时提示完成或超限。
- 只统计当前自然月且日期不超过今天的工记，不计未来计划。
- 首页与本月统计显示持续状态；同月、同档位、同配置只弹一次 Toast。
- 本版是应用内提醒，不主动申请系统通知权限；它也不是消费支出预算。

### 3. 完整工记 CSV

- 「我的 → 数据与安全 → 对账导出 → 完整工记 CSV」。
- 导出全部有效工记的 38 列：记录 / 工作 / 时间 / 工时 / 奖扣 / 备注 / 照片 ID / 结算 ID / 周期来源，以及完整计薪快照。
- 提供日期、工作和计薪类型的数据层筛选能力，当前页面默认导出全部。
- 文本以 `= + - @` 等公式前缀开头时自动转义，降低 Excel / WPS 公式注入风险。
- 月薪的「基础 / 合计」列仍是单笔折算参考，正式到手金额以结算单为准。
- CSV 只含有效工记，不含照片本体、回收站记录或完整结算对象，不能用于完整恢复；换机仍用 JSON 搬家包。

### 4. 周期记工

- 「记录 → 周期记工」新建每日、每周或每月规则。
- 支持工作日多选、每月 1–31 日、小月月末、开始 / 结束日期、工时、计件数量、奖金、扣款和备注。
- 页面显示待补记预览和冲突跳过数量，确认后原子生成普通工记。
- 默认只处理到昨天，不提前给今天计薪；需要今天可用手动工记。
- 同岗位同日已有工记、休息、周期已结算或当日合计会超过 24 小时时跳过。
- 「打开 App 自动补到昨天」默认关闭，只有用户明确开启的规则才自动执行；应用未打开时不会后台生成。
- 删除规则只停止以后生成，不删除历史工记；有规则的工作不能直接删除，需先处理规则。
- 生成记录带规则来源；规则删除后来源 ID 保留用于审计。

## 审计修复

### 数据与计薪

- 损坏、高版本或无法访问的本地账本停止启动并进入恢复页，可导出原始内容；不再回退旧缓存后用空数据覆盖。
- Store 写操作同步推进内部状态引用，降低同一事件循环内连续修改读取旧状态的风险。
- 工记新增 / 编辑补齐工作、日期、数值和归档校验；借支补齐岗位、金额、日期和已结算周期校验，失败不再误报成功。
- 固定月薪整月图表与本月合计统一；同日多段月薪工记只计一次基础工资。
- 月薪汇总按每天的历史计薪快照计算；同月规则变化时按各日期快照折算，规则一致且为固定月薪时才直接按整月发放。
- 工作删除保护与周期规则关联保持一致。

### 备份与恢复

- 普通 / 加密备份文件名增加时分秒，同日连续导出不再互相覆盖。
- 全空白密码被拒绝；密码首尾空格处理统一；高版本加密备份明确提示升级。
- 搬家包清单支持周期规则数量校验，旧包缺省继续兼容。
- 覆盖导入、清空、撤销结算前等待快照事务完成；失败时取消操作，不再“无快照也继续”。
- 新工记照片写入失败时移除未兑现的照片引用，工记文字数据仍保留。

### 原生与通知接口

- 发薪通知 ID 改为工作 ID 的稳定散列，不再受工作数组排序影响。
- 启动同步不再自行弹通知权限框，权限只在用户主动操作时申请。
- Android 保存文件校验文件名，禁止路径分隔符、控制字符和超长名称。
- 同名文件先完整写入临时文件，再替换本应用所有的目标文件；写入失败时保留旧文件。
- 文件读取增加取消异常处理，保存结果继续沿用 `path / uri`，清理接口沿用 `deleted`。
- 真机发现部分 ROM 的 WebView `env(safe-area-inset-*)` 为 0；Android 壳现把系统 WindowInsets 映射到现有 `--safe-*` 变量，并在页面开始 / 完成时重新应用，修复状态栏遮挡。

## 数据兼容

- schema 继续冻结在 **v7**，存储键仍为 `xinshi.state.v7`。
- 新增 `settings.budget?`、`AppState.recurringRules?`、`Entry.recurringRuleId?`，均为可选字段。
- 旧备份、旧搬家包、旧快照可继续导入；老版本读取新备份时会忽略新增可选字段，主账本结构不变。
- 已生成结算单是历史快照，本次统计修正不回写结算单。

## 验证

```bash
pnpm test                 # 239 个单元测试，串行执行避免本机临时文件并发问题
pnpm build                # TypeScript + Vite 生产构建
pnpm test:e2e             # 既有场景 + v1.2.0 场景
node scripts/functional-v120.mjs  # 需先 pnpm preview
pnpm android:sync         # 同步 Web 资源到 Android
```

Android 默认 `versionCode 1200` / `versionName 1.2.0`，Service Worker 缓存升级为 `xinshi-v26`。

最终验收结果：239 / 239 单测、119 / 119 浏览器场景、135 / 135 响应式组合通过。Redmi 真机覆盖 1.1.0 后 6 笔工记 / 1 份工作保持不变，分类、周期页、CSV 与同名覆盖通过；最终 R8 非调试包冷启动与安全区显示正常。真机记录见 `test-results-android-v120/result.json` 和同目录截图。

## 已知边界

- 同月多次修改月薪合同只能按每日快照做近似折算；如需严格的入职 / 离职 / 调薪生效区间，应另建工作或在结算时核对额外奖扣。
- 周期规则不运行在系统后台；只有打开 App 才补记，自动补记也只处理到昨天。
- 预算提醒本版不接系统通知；需要系统级提醒时可继续使用现有每日记工 / 发薪通知。
- 完整 CSV 是对账导出，不是可导入的备份格式。
- Android 9 及以下的原生公共下载保存仍受系统能力限制，界面会返回明确错误。
